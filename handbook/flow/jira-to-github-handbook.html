Jira 子任務 → GitHub Issue
自動化開發指導手冊

本手冊描述一套以 Google Apps Script + GitHub Actions 組成的輕量自動化流程： 依據指定母單號，抓取 Label 為 Alice 的子任務， 每日凌晨 4 點自動將任務描述同步開立為 GitHub Issue。

適用：Google Apps Script (V8) Jira Cloud REST API v3 GitHub Actions
OVERVIEW

整體架構

┌─ 手動執行（一次性或需要更新時）──────────────────────────┐ │ │ │ GAS: fetchAliceSubtasks() │ │ → 呼叫 Jira API 取得母單 {PARENT_ISSUE_KEY} 的所有 Subtask │ │ → 篩選 Label 包含 "Alice" 的子任務 │ │ → 將 Issue Key 寫入 Google Sheets（Sheet: task_queue） │ │ │ └────────────────────────────────────────────────────────────┘ ┌─ 每日凌晨 4:00（GAS Time-based Trigger）──────────────────┐ │ │ │ GAS: dispatchToGitHub() │ │ → 讀取 Sheets task_queue，取出 status = "pending" 的列 │ │ → 每筆 Issue Key 各自觸發一次 GitHub workflow_dispatch │ │ → 更新該列 status = "dispatched" │ │ │ └────────────────────────────────────────────────────────────┘ ┌─ GitHub Actions: sync-jira-issue.yml ──────────────────────┐ │ │ │ Input: jira_issue_key │ │ → 呼叫 Jira API 取得該 Issue 的 summary / description │ │ → 以 summary 為 title、description 為 body │ │ → 呼叫 GitHub API 建立 GitHub Issue │ │ │ └────────────────────────────────────────────────────────────┘
設計決策備忘：GitHub workflow dispatch 採每筆各自觸發（方案 B）， 錯誤隔離、每個 run 有獨立 log，單筆失敗可直接在 GitHub Actions UI 手動 re-run， 不影響其他筆。
STEP 0

前置準備

需要準備的帳號與 Token

項目說明取得方式
Jira API Token 用於 GAS 及 GitHub Actions 呼叫 Jira Jira → 帳號頭像 → Manage account → Security → API tokens
Jira Email 與 API Token 搭配做 Basic Auth 登入 Jira 的 email
Jira Base URL 例如 https://your-org.atlassian.net Jira 網址列複製
GitHub Fine-grained PAT GAS 觸發 workflow dispatch 用，只對指定 repo 的 Actions 有效 見下方建立步驟
GitHub Token（Actions 內部用） 建立 GitHub Issue 用 直接用 secrets.GITHUB_TOKEN，GitHub 自動產生，無需額外建立

① Jira API Token 建立與設定

  1. 登入 Jira，點右上角頭像 → Manage account
  2. 上方頁籤選 Security → API tokens → Create API token
  3. 輸入名稱（例如 gas-jira-sync），複製產生的 token 值（離開後不再顯示）
  4. 此 token 需設定到兩個地方：
    設定位置屬性／Secret 名稱說明
    GAS Script PropertiesJIRA_API_TOKENGAS 呼叫 Jira API 用
    GitHub Repository SecretsJIRA_API_TOKENGitHub Actions 呼叫 Jira API 用

② 確認你的 GitHub 帳號名稱

  1. 登入 GitHub，點右上角頭像
  2. 第一行顯示的就是你的帳號名稱（例如 ocean-tsai），或進入 Settings → Public profile 查看 Username 欄位
  3. 記下這個名稱，後續需填入 GitHub Secrets 的 ALLOWED_GITHUB_ACTOR

③ GitHub Fine-grained PAT 建立步驟

  1. GitHub 右上角頭像 → Settings
  2. 左側選單最底部 → Developer settings
  3. Personal access tokens → Fine-grained tokens → 右上角 Generate new token
  4. 填寫設定：
    欄位填入值
    Token namegas-jira-sync（自訂）
    Expiration建議 90 天或 1 年
    Resource owner下拉選公司組織名稱（例如 104corp），不要選個人帳號，否則看不到公司 repo
    Repository accessOnly select repositories → 選目標 repo
    Permissions → ActionsRead and write（勾選 Actions 後，右側下拉選 Read and write）
    Permissions → MetadataRead-only（GitHub 自動勾選，必要項目，不需更動）
    其他所有 Permissions維持 No access
  5. 點 Generate token，立刻複製 token 值（離開頁面後不會再顯示）
  6. 將 token 值貼入 GAS Script Properties 的 GITHUB_TOKEN 欄位（只需設定這一個地方）
Fine-grained PAT vs Classic PAT：Classic PAT 一旦洩漏，持有者可對你帳號下所有 repo 操作； Fine-grained PAT 限定單一 repo 且只開 Actions 權限，洩漏後攻擊面只有這一個 repo 的 workflow 觸發，其他全部無效。 本方案一律使用 Fine-grained PAT，不使用 Classic PAT。
組織管理員審核：Resource owner 選組織後，組織管理員可能需要先在 GitHub 組織設定中允許 Fine-grained PAT 存取。若送出後看到「等待審核」提示， 需請組織管理員到 Organization Settings → Personal access tokens → Pending requests 審核通過後才能使用。 若組織管理員尚未開放此功能，可暫時改用 Classic PAT（選 workflow scope）， 功能相同，但權限範圍較大，請妥善保管。

  1. 開啟 GAS 專案，上方選單點 專案設定（齒輪圖示）
  2. 往下捲到 指令碼屬性 區塊，點 新增指令碼屬性
  3. 依下表逐一新增，每筆填入屬性名稱與對應的值：
    屬性名稱填入值來源
    JIRA_BASE_URLJira 網址列，例如 https://your-org.atlassian.net
    JIRA_EMAIL登入 Jira 的 email
    JIRA_API_TOKEN步驟 ① 產生的 Jira API Token
    JIRA_PARENT_KEY母單 Issue Key，例如 VIPOP-999
    SPREADSHEET_ID試算表網址中 /d/ 與 /edit 之間那段
    GITHUB_TOKEN步驟 ③ 產生的 Fine-grained PAT
    GITHUB_OWNERGitHub 組織或帳號名稱
    GITHUB_REPO目標 Repository 名稱

⑤ GitHub Repository Secrets 設定方式

  1. 進入目標 GitHub repo 頁面
  2. 上方頁籤點 Settings
  3. 左側選單 → Secrets and variables → Actions
  4. 點 New repository secret，依下表逐一新增：
    Secret 名稱填入值來源
    JIRA_BASE_URLJira 網址列，例如 https://your-org.atlassian.net
    JIRA_EMAIL登入 Jira 的 email
    JIRA_API_TOKEN步驟 ① 產生的 Jira API Token（與 GAS 同一組）
    ALLOWED_GITHUB_ACTOR步驟 ② 確認的 GitHub 帳號名稱
注意：Jira API Token 會同時存在 GAS Script Properties 與 GitHub Secrets 兩邊， 填入的值相同，只是兩個系統各自需要一份。請勿將任何 Token 直接寫死在程式碼中。

GitHub Actions 身份驗證說明

workflow 收到 dispatch 請求後，第一步會驗證觸發者的 GitHub 帳號是否在白名單內。 這個帳號資訊（triggering_actor）是 GitHub 系統自動判斷的， 來自 Fine-grained PAT 所綁定的帳號，無法偽造。 已在步驟 ⑤ 設定到 ALLOWED_GITHUB_ACTOR。

PART 2

GAS Script A — 抓取 Jira 子任務

  • Google Apps Script
  • Jira REST API v3
  • Google Sheets

此 Script 負責：呼叫 Jira API 取得指定母單下所有 Subtask， 篩選 Label 包含 Alice 的項目，寫入試算表 task_queue sheet， 預設 status 為 pending。

執行時機：此函式為手動執行（或需要重新抓取時執行）， 不需設排程。建議在確認母單號、試算表都就緒後，執行一次。

建立 GAS 專案

  1. 前往 script.google.com，新增專案，命名為 JiraAliceSync。
  2. 建立兩個檔案：Config.gs（存放常數）與 FetchTasks.gs（主邏輯）。
  3. 進入「專案設定」→「指令碼屬性」，新增下方表格的所有屬性。

FetchTasks.gs
// ── CONFIG：從 Script Properties 讀取，避免 Token 寫死在程式碼 ──
const CONFIG = {
  get JIRA_BASE_URL()   { return PropertiesService.getScriptProperties().getProperty('JIRA_BASE_URL'); },
  get JIRA_EMAIL()      { return PropertiesService.getScriptProperties().getProperty('JIRA_EMAIL'); },
  get JIRA_API_TOKEN()  { return PropertiesService.getScriptProperties().getProperty('JIRA_API_TOKEN'); },
  get JIRA_PARENT_KEY() { return PropertiesService.getScriptProperties().getProperty('JIRA_PARENT_KEY'); },
  get SPREADSHEET_ID()  { return PropertiesService.getScriptProperties().getProperty('SPREADSHEET_ID'); },
  SHEET_NAME: 'task_queue',
  ALICE_LABEL: 'Alice',
};

// ─────────────────────────────────────────────────────────────────

/**
 * 主入口：抓取母單下所有 Label = Alice 的子任務，寫入試算表
 * 手動執行此函式，或需要重新同步時執行
 */
function fetchAliceSubtasks() {
  const subtasks = _getSubtasksFromJira(CONFIG.JIRA_PARENT_KEY);
  const aliceTasks = subtasks.filter(t => t.labels.includes(CONFIG.ALICE_LABEL));

  if (aliceTasks.length === 0) {
    Logger.log('未找到 Label = Alice 的子任務');
    return;
  }

  _writeTasksToSheet(aliceTasks);
  Logger.log(`完成：共寫入 ${aliceTasks.length} 筆任務`);
}

/**
 * 呼叫 Jira API 取得母單的所有子任務（issuetype = Subtask）
 * @param {string} parentKey - 母單 Issue Key，例如 "VIPOP-999"
 * @returns {Array} subtask 陣列，每筆包含 key, summary, labels
 */
function _getSubtasksFromJira(parentKey) {
  const jql = `parent = "${parentKey}" AND issuetype = Subtask`;
  const url = `${CONFIG.JIRA_BASE_URL}/rest/api/3/search`
    + `?jql=${encodeURIComponent(jql)}`
    + `&fields=summary,labels`
    + `&maxResults=100`;

  const token = Utilities.base64Encode(`${CONFIG.JIRA_EMAIL}:${CONFIG.JIRA_API_TOKEN}`);
  const response = UrlFetchApp.fetch(url, {
    method: 'get',
    headers: {
      'Authorization': `Basic ${token}`,
      'Accept': 'application/json',
    },
    muteHttpExceptions: true,
  });

  if (response.getResponseCode() !== 200) {
    throw new Error(`Jira API 錯誤: ${response.getResponseCode()} ${response.getContentText()}`);
  }

  const data = JSON.parse(response.getContentText());
  return data.issues.map(issue => ({
    key: issue.key,
    summary: issue.fields.summary,
    labels: issue.fields.labels || [],
  }));
}

/**
 * 將子任務陣列寫入 Google Sheets
 * 若 issue_key 已存在則跳過（不重複寫入）
 * @param {Array} tasks - { key, summary, labels }
 */
function _writeTasksToSheet(tasks) {
  const ss    = SpreadsheetApp.openById(CONFIG.SPREADSHEET_ID);
  const sheet = ss.getSheetByName(CONFIG.SHEET_NAME);
  const now   = new Date().toISOString();

  // 取得已存在的 issue_key 清單，避免重複寫入
  const lastRow   = sheet.getLastRow();
  const existKeys = lastRow > 1
    ? sheet.getRange(2, 1, lastRow - 1, 1).getValues().flat()
    : [];

  const newRows = tasks
    .filter(t => !existKeys.includes(t.key))
    .map(t => [t.key, t.summary, 'pending', now, '', '']);

  if (newRows.length === 0) {
    Logger.log('所有任務均已存在於試算表，無新增');
    return;
  }

  sheet.getRange(lastRow + 1, 1, newRows.length, 6).setValues(newRows);
  Logger.log(`新增 ${newRows.length} 筆，跳過 ${tasks.length - newRows.length} 筆（已存在）`);
}
PART 3

GAS Script B — 排程觸發 GitHub Dispatch

  • Google Apps Script
  • GitHub API
  • Google Sheets

此 Script 負責：每日凌晨 4:00 讀取試算表中 status = pending 的列， 逐一呼叫 GitHub API 觸發 workflow_dispatch， 成功後將該列 status 更新為 dispatched。

/**
 * 排程主入口：凌晨 4:00 由 Time-based Trigger 自動呼叫
 * 讀取試算表 pending 任務，逐一觸發 GitHub workflow dispatch
 */
function dispatchToGitHub() {
  const ss    = SpreadsheetApp.openById(CONFIG.SPREADSHEET_ID);
  const sheet = ss.getSheetByName(CONFIG.SHEET_NAME);
  const rows  = _getPendingRows(sheet);

  if (rows.length === 0) {
    Logger.log('目前無 pending 任務');
    return;
  }

  rows.forEach(({ rowIndex, issueKey }) => {
    try {
      _triggerWorkflowDispatch(issueKey);
      _updateRowStatus(sheet, rowIndex, 'dispatched');
      Logger.log(`✓ dispatched: ${issueKey}`);
    } catch (e) {
      _updateRowStatus(sheet, rowIndex, 'error', e.message);
      Logger.log(`✗ error: ${issueKey} → ${e.message}`);
    }
  });
}

/**
 * 從試算表取出所有 status = "pending" 的列
 * @returns {Array} [{ rowIndex, issueKey }]
 */
function _getPendingRows(sheet) {
  const lastRow = sheet.getLastRow();
  if (lastRow < 2) return [];

  const data = sheet.getRange(2, 1, lastRow - 1, 3).getValues();
  return data
    .map(([issueKey, summary, status], i) => ({ rowIndex: i + 2, issueKey, status }))
    .filter(r => r.status === 'pending' && r.issueKey);
}

/**
 * 呼叫 GitHub API 觸發 workflow_dispatch
 * @param {string} issueKey - Jira Issue Key，例如 "VIPOP-1234"
 */
function _triggerWorkflowDispatch(issueKey) {
  const props  = PropertiesService.getScriptProperties().getProperties();
  const url    = `https://api.github.com/repos/${props.GITHUB_OWNER}/${props.GITHUB_REPO}`
                + `/actions/workflows/${props.GITHUB_WORKFLOW_ID}/dispatches`;

  const payload = {
    ref: props.GITHUB_REF,
    inputs: { jira_issue_key: issueKey },
  };

  const response = UrlFetchApp.fetch(url, {
    method: 'post',
    headers: {
      'Authorization': `Bearer ${props.GITHUB_TOKEN}`,
      'Accept': 'application/vnd.github+json',
      'X-GitHub-Api-Version': '2022-11-28',
    },
    contentType: 'application/json',
    payload: JSON.stringify(payload),
    muteHttpExceptions: true,
  });

  // workflow_dispatch 成功回傳 204 No Content
  const code = response.getResponseCode();
  if (code !== 204) {
    throw new Error(`GitHub API 錯誤: ${code} ${response.getContentText()}`);
  }
}

/**
 * 更新試算表指定列的 status 與 dispatched_at / note
 */
function _updateRowStatus(sheet, rowIndex, status, note = '') {
  const now = new Date().toISOString();
  sheet.getRange(rowIndex, 3).setValue(status);
  sheet.getRange(rowIndex, 5).setValue(now);
  sheet.getRange(rowIndex, 6).setValue(note);
}

// ─────────────────────────────────────────────
//  排程建立（只需執行一次）
//  在 GAS 編輯器手動執行 setupTrigger()
// ─────────────────────────────────────────────
function setupTrigger() {
  // 先刪除舊的同名 trigger，避免重複
  ScriptApp.getProjectTriggers()
    .filter(t => t.getHandlerFunction() === 'dispatchToGitHub')
    .forEach(t => ScriptApp.deleteTrigger(t));

  ScriptApp.newTrigger('dispatchToGitHub')
    .timeBased()
    .everyDays(1)
    .atHour(4)
    .create();

  Logger.log('排程建立完成：每日 04:00 執行 dispatchToGitHub');
}
setupTrigger() 只需執行一次。 執行後可在「觸發條件」頁面確認排程是否建立成功。 重複執行會先清除舊的再重建，不會產生重複排程。
PART 4

GitHub Actions Workflow

  • GitHub Actions
  • Jira REST API v3
  • GitHub Issues API

此 workflow 由 GAS 觸發，接收 jira_issue_key 作為 input， 取回 Jira 任務的 summary 與 description，然後在 GitHub repo 建立 Issue。

檔案位置

在 repo 中建立以下路徑的檔案：.github/workflows/sync-jira-issue.yml

GitHub Secrets 設定

前往 repo → Settings → Secrets and variables → Actions，新增：

Secret 名稱說明
JIRA_BASE_URLJira 網域，例如 https://your-org.atlassian.net
JIRA_EMAILJira 帳號 email
JIRA_API_TOKENJira API Token
ALLOWED_GITHUB_ACTOR允許觸發此 workflow 的 GitHub 帳號名稱（用於身份驗證）
建立 GitHub Issue 使用 secrets.GITHUB_TOKEN，這是 Actions 自動提供的， 不需要額外建立 Secret。
.github/workflows/sync-jira-issue.yml
name: Sync Jira Issue to GitHub

on:
  workflow_dispatch:
    inputs:
      jira_issue_key:
        description: 'Jira Issue Key (e.g. VIPOP-1234)'
        required: true
        type: string

jobs:
  create-github-issue:
    runs-on: ubuntu-latest
    permissions:
      issues: write

    steps:
      - name: Verify caller identity
        run: |
          # triggering_actor 是 GitHub 系統判斷的觸發者帳號，非外部傳入，無法偽造
          ACTOR="${{ github.triggering_actor }}"
          ALLOWED="${{ secrets.ALLOWED_GITHUB_ACTOR }}"
          if [ "$ACTOR" != "$ALLOWED" ]; then
            echo "❌ Unauthorized: triggered by '$ACTOR', expected '$ALLOWED'"
            exit 1
          fi
          echo "✓ Identity verified: $ACTOR"

      - name: Fetch Jira Issue
        id: jira
        run: |
          # 呼叫 Jira REST API v3 取得 issue 詳細資訊
          RESPONSE=$(curl -s -u "${{ secrets.JIRA_EMAIL }}:${{ secrets.JIRA_API_TOKEN }}" \
            -H "Accept: application/json" \
            "${{ secrets.JIRA_BASE_URL }}/rest/api/3/issue/${{ inputs.jira_issue_key }}?fields=summary,description")

          # 解析 summary
          SUMMARY=$(echo "$RESPONSE" | jq -r '.fields.summary')

          # description 為 Atlassian Document Format (ADF)，轉換為純文字
          # 取 ADF 中所有 text node 的內容串接
          DESCRIPTION=$(echo "$RESPONSE" | jq -r '
            [.fields.description.content[]? |
              .. | .text? | strings] | join("\n")
          ')

          # 若 description 為空，填入預設說明
          if [ -z "$DESCRIPTION" ]; then
            DESCRIPTION="（Jira 描述為空）"
          fi

          # 輸出供後續 step 使用（使用 heredoc 處理多行）
          echo "summary=$SUMMARY" >> "$GITHUB_OUTPUT"
          {
            echo "description<> "$GITHUB_OUTPUT"

      - name: Create GitHub Issue
        uses: actions/github-script@v7
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
          script: |
            const issueKey  = `${{ inputs.jira_issue_key }}`;
            const summary   = `${{ steps.jira.outputs.summary }}`;
            const desc      = `${{ steps.jira.outputs.description }}`;
            const jiraUrl   = `${{ secrets.JIRA_BASE_URL }}/browse/${issueKey}`;

            const body = [
              `> 此 Issue 由自動化流程從 Jira 同步建立`,
              `> Jira 連結：[${issueKey}](${jiraUrl})`,
              ``,
              desc,
            ].join('\n');

            const result = await github.rest.issues.create({
              owner: context.repo.owner,
              repo:  context.repo.repo,
              title: `[${issueKey}] ${summary}`,
              body,
              labels: ['from-jira'],
            });

            core.info(`GitHub Issue 建立成功：${result.data.html_url}`);
關於 Jira Description 格式：Jira Cloud 的 description 使用 Atlassian Document Format（ADF，一種 JSON 結構）儲存， workflow 中已使用 jq 將所有 text node 攤平取出。 若原始描述包含複雜表格或巢狀 Panel，轉換結果為純文字，格式可能不完整， 這在臨時方案下是可接受的。

驗收 Checklist

Part 1 — 試算表

  1. 試算表已建立，Sheet 名稱為 task_queue，欄位標題與規格吻合。
  2. Spreadsheet ID 已複製備用。

Part 2 — 子任務抓取

  1. GAS Script Properties 的 5 個屬性均已填入。
  2. 手動執行 fetchAliceSubtasks()，Logger 顯示寫入筆數。
  3. 試算表中出現對應子任務，status 欄位為 pending。
  4. 重複執行不產生重複列。

Part 3 — 排程觸發

  1. GAS Script Properties 的 5 個 GitHub 相關屬性均已填入。
  2. 手動執行 dispatchToGitHub()，Logger 顯示每筆 ✓ dispatched。
  3. GitHub Actions 頁面出現對應數量的 workflow run，狀態為 running 或 success。
  4. 試算表中 status 欄位更新為 dispatched，dispatched_at 有值。
  5. 手動執行 setupTrigger()，在 GAS「觸發條件」頁面確認排程存在。

Part 4 — GitHub Actions

  1. GitHub Secrets 的 4 個屬性均已填入（含 ALLOWED_GITHUB_ACTOR）。
  2. workflow 檔案已 push 到 main branch。
  3. 在 Actions 頁面手動觸發一次，傳入一個真實的 Jira Issue Key 測試。
  4. 第一個 step「Verify caller identity」顯示 ✓ Identity verified: {你的帳號}，沒有 exit 1。
  5. GitHub Issues 頁面出現新 Issue，title 格式為 [VIPOP-XXXX] {summary}，body 包含 Jira 連結與描述。
  6. Issue 帶有 from-jira label。
  7. 用其他帳號或直接改 ALLOWED_GITHUB_ACTOR 為不存在的值，確認 workflow 第一步會 fail 並中止。
全部通過後：整套流程完整驗收。 後續每日凌晨 4:00 GAS 排程將自動觸發， 直到系統正式方案完成接手為止。
