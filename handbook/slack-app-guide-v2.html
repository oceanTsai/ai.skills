Slack App 建置指南

給第一次建 Slack App 的前端工程師。全程照著跑不需思考,每個設定會告訴你「必做/選做/跳過」以及為什麼。目標:拿到 xoxb-... token,並確認頻道裡 @ 得到你的 bot。

這份指南只涵蓋 Slack 這一側。之後你會需要一個 endpoint(如 GAS Web App)來接收事件,那部分不在這裡。這裡的終點是「Bot 已安裝、能被 @、拿到 token,隨時可以接 endpoint」。

A整體概念(30 秒)

Slack 沒有真正的「機器人」物件。你建的是一個 Slack App(容器),它附帶一個 Bot User(頻道裡被 @ 的那個化身)。你要幫這個 Bot 貼上權限標籤(Scopes),再把整個 App 安裝到 workspace,就會得到一組 xoxb- 開頭的 token——這就是 Bot 之後和 Slack API 對話用的通行證。

整套流程 建 App(容器)→ 加 Scope(貼權限貼紙)→ 設 Bot User(定名字)→ Install(安裝)→ 拿到 token → 邀請進頻道

B標示說明

每個設定會標上以下三種之一:

必做 選做 跳過
  • 必做 — 不做 Bot 就跑不起來
  • 選做 — 依情境決定,通常先不做也 OK
  • 跳過 — 這次用不到,不用管它是什麼

1階段 1 · 建立 App

1
前往 Slack API 主控台
必做
網址:api.slack.com/apps 用你的公司 Slack 帳號登入。如果它問你 workspace 網址,填公司的(例如 104corp.slack.com)。
2
點綠色「Create an App」
必做
跳出對話框後,四個選項選 「Blank app」(右下角)。
為什麼:其他三個(AI agent、Starter app、From a manifest)都預裝了 Bolt 框架,假設你要自架 Node/Python 伺服器。Blank app 是空殼,完全自由。
3
填 App name 和 Workspace
必做
App name:你的 bot 名字(例如 Alice)。之後可以改。
Workspace:下拉選公司那個。
陷阱 Workspace 選了不能改。選對再按 Create。個人測試 workspace 和公司 workspace 別搞混。
4
按 Create App,進管理頁
必做
建好會自動進 Basic Information 頁,左側一長排選單就是設定清單。

2階段 2 · 加權限(Scopes)

為什麼先做這步? 新版介面下,沒加 scope,App Home 的 bot user 設定會被鎖住。指南把加 scope 放前面,順序上比較不會卡。
1
左側點 OAuth & Permissions
必做
左側 Features → OAuth & Permissions
2
往下捲到「Scopes / 權限範圍」
必做
會看到兩塊:Bot Token Scopes(機器人權杖權限範圍)和 User Token Scopes(使用者權杖權限範圍)。
別加錯地方 只加在上面那塊 Bot Token Scopes。下面 User Token Scopes 是「以某個真人使用者身分」操作 API 用的,你不需要。
3
加兩個必要 scope
必做
點 Add an OAuth Scope,搜尋並選這兩個:
app_mentions:read · 讓 Bot 收到「有人 @ 它」的事件
chat:write · 讓 Bot 能發訊息到頻道
為什麼只加這兩個:你的第一版功能就是「被 @ → 收事件 → 回訊息」,這兩個 scope 剛好覆蓋。之後想加功能(讀私訊、加 emoji 反應等)再回來加對應 scope。
4
Restrict API Token Usage
跳過
同頁再往下有個 IP 白名單設定,不要碰。
為什麼跳過:如果你用 GAS 當 endpoint,GAS 出口 IP 是浮動的,一旦設了白名單 GAS 呼叫 Slack API 會全部被擋。有固定 IP 的伺服器才適合設。

3階段 3 · 設定 Bot User

1
左側點 App Home
必做
左側 Features → App Home 加了 scope 後,原本被鎖住的區塊現在會開啟。
2
找到「App Display Name」→ Edit
必做
會跳出兩個欄位:
Display Name:Bot 發訊息時顯示的名字,可含大小寫、空白、中文(例:Alice、Alice 小助手)
Default Username:被 @ 時實際打的 handle,必須全小寫、無空白(例:alice)
為什麼分兩個名字:跟真人一樣。你在 Slack 顯示「蔡振華」,但可能 @ 打 @ocean。Bot 沿用同一套邏輯。
撞名會被加編號 如果 workspace 已有人 handle 是 alice,系統會自動幫你變成 alice2。若真的撞名,建議命名 alice-bot 或 f2e-alice 這種明顯不像人名的。
3
開啟 Always Show My Bot as Online
必做
頭像旁那顆綠點的開關。
為什麼開:不開的話 Bot 永遠顯示灰色離線,使用者以為壞掉不敢用。開啟後永遠綠點,符合實情(你的 Bot 本來就 24/7 待命)。
4
Show Tabs → Messages Tab
選做
Messages Tab 是 Bot 的「一對一私聊視窗」。目前開不開都行,但別勾底下的「Allow users to send Slash commands and messages...」。
為什麼不勾:那個勾選會讓私聊視窗開放輸入,但你目前只訂了頻道 @ 事件、沒訂私訊事件——使用者打字 Bot 不會回,體驗更差。之後若要開放私訊,要另外加 im:history scope 並訂 message.im 事件才對。
5
Home Tab
跳過
Home Tab 是 Bot 專屬的一頁 UI 畫面,要用 Block Kit 寫。第一版純文字對答用不到。

4階段 4 · 安裝到 Workspace

這步之後才會產生真正的 xoxb- token。安裝前確認 Scope 已加完——安裝後若再加 scope,還要再點一次 Reinstall。
1
左側點 Install App
必做
左側 Settings → Install App
2
按 Install to Workspace
必做
會跳到授權頁,顯示這個 App 要拿哪些權限(就是你剛才加的 scopes)。
組織可能需要管理員核准 若公司開了 App 核准機制,按下去可能不會直接裝好,而是變成「送出申請」等 admin 批准。找你們的 Slack 管理員(通常是 IT)加速。
3
按 Allow 完成授權
必做
授權後會跳回 Install App 頁,這時上面會出現 Bot User OAuth Token,格式 xoxb-...。

5取得並保管 Token

1
複製 Bot User OAuth Token
必做
Install App 頁 → Bot User OAuth Token → Copy 貼到暫時安全的地方(不是 slack 訊息!用密碼管理器或本機記事本)。
Token 保管三原則 1. 不要貼進 Slack / Line / 任何聊天室(等於公開)
2. 不要 commit 進 Git,不要寫進程式碼
3. 之後放進 GAS 的 Script Properties,或環境變數
2
複製 Signing Secret 和 Verification Token
選做
Basic Information 頁 → App Credentials 區塊
Signing Secret:用來驗證請求真的來自 Slack(HMAC 簽章)
Verification Token:舊版驗證方式,payload 內會帶
為什麼「選做」:如果 endpoint 是 GAS,GAS 拿不到 request header,標準 HMAC 驗簽章做不了,只能退而用 Verification Token 比對 payload。等你接 endpoint 時再回來拿。

6驗證 Bot 能被 @

此時 Bot 已安裝、有 token,但頻道裡還 @ 不到——因為還沒被邀請進頻道。
1
在 Slack 找一個測試頻道
必做
建議先建一個 #alice-test 之類的頻道自己測,別直接丟到有很多人的正式頻道。
2
邀請 Bot 進頻道
必做
頻道輸入框打:
/invite @alice
alice 換成你剛才設定的 Default Username。
或用視覺化方式 頻道右上角「頻道詳細資料」→「整合」→「App」→「Add an App」,搜尋你的 App 名稱後 Add。
3
試著 @ 它
必做
頻道打 @alice hello。目前 Bot 不會回應(因為還沒接 endpoint),但重點是:
✅ 打 @ali 時應該會出現 Alice 的自動完成建議
✅ 送出後,@alice 應顯示為可點擊的 mention(藍字),不是純文字
看到這兩個,代表 Slack 這側完全正確,可以進入「接 endpoint」階段。

7完成檢查表

  • App 已建立(Blank app,workspace 選對)
  • Bot Token Scopes 加了 app_mentions:read、chat:write
  • App Home 的 Display Name / Default Username 設定完成
  • Always Show My Bot as Online 已開啟
  • Install to Workspace 已完成、Allow 已按
  • 已拿到 xoxb- token 並安全保管
  • Bot 已被 /invite 進測試頻道
  • 頻道內 @ 提及能看到藍字 mention

八項都打勾,Slack 這側完成。接下來可以進入「接 GAS Web App endpoint」階段。

8名詞速查

名詞白話解釋
App裝著 Bot、權限、事件訂閱等設定的容器
Bot UserApp 附帶的化身,頻道裡被 @ 的那個
Scope權限標籤,決定 Bot 能做什麼
Token(xoxb-)Bot 呼叫 Slack API 時的通行證
Workspace整個 Slack 組織空間(例如 104 Corp)
ChannelWorkspace 裡的頻道
EventSlack 主動推給你的通知(有人 @ 了、加入頻道了)
Endpoint你這邊接收事件的 URL(之後會是 GAS Web App 網址)
Mention@ 提及。@alice 就是一則 mention

9哪些設定不用碰

左側選單很長,以下這些第一次建 App 完全可以無視:

選項是什麼為何跳過
CollaboratorsApp 的共同開發者一個人做就用不到
Socket Mode用 WebSocket 收事件,不用公開 endpoint你有 GAS Web App URL,走 HTTP 就好
AgentsSlack 官方 AI agent 框架綁 Bolt/CLI,跟你架構不合
Work Object Previews訊息裡連結的預覽卡片純內部工具用不到
Workflow StepsSlack Workflow Builder 的自訂步驟你不用 Slack Workflow
Org Level AppsEnterprise Grid 的組織級部署只有 Enterprise 方案才有
Incoming Webhooks單向推訊息的簡化方式你要雙向,走 Events API 更完整
Interactivity & Shortcuts按鈕/表單/modal 的事件沒做互動 UI 不用
Slash Commands自訂 /alice 指令之後想做再開,目前用 @ 就夠
MCP Servers (New)對外提供 MCP server 給 AI 呼叫方向相反的新功能,現在不用
App Manifest用 YAML/JSON 一次帶完所有設定手動點清楚就好,重複建才用得到
Manage Distribution把 App 公開發佈到 Marketplace內部工具不用公開
Submit to Slack Marketplace同上同上

10常見問題

App Home 看不到 Bot 名字設定?

Scope 沒加。回階段 2 加完 app_mentions:read 和 chat:write,再回 App Home 就會解鎖。

Install to Workspace 按了說要 admin 核准?

公司開了 App 核准機制。送出申請後找 Slack 管理員批准,不是你的問題。

Workspace 下拉選單裡看不到公司?

你的 Slack 帳號沒登入到那個 workspace。到 Slack 客戶端切到公司 workspace 一次,再回 api.slack.com。

@ Bot 沒反應?

三種可能:(1) Bot 沒被 /invite 進頻道;(2) 還沒接 endpoint(這個指南範圍內是正常的);(3) 打錯 username。

加了新 scope 之後?

頁面頂端會出現黃色提示「You've changed permission scopes...」,按 reinstall your app。已經拿到的 xoxb- token 通常不變。

介面中英混雜?

Slack 中文化沒做完整,忽略就好,不影響操作。

不小心點到「Delete App」?

已建立的 App 刪除後不可復原,只能重建。刪除按鈕在 Basic Information 頁最底部,誤點會有二次確認。
